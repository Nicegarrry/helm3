# Wave 1 raw artifact journal evidence

Date: 2026-09-15. Scope: library-only acceptance of the raw execution-artifact portion of [JOURNAL #31](https://github.com/Nicegarrry/helm3/issues/31), delivered through [PR #40](https://github.com/Nicegarrry/helm3/pull/40) and the provider-free same-SQLite integration in [PR #42](https://github.com/Nicegarrry/helm3/pull/42). Native producer wiring remains later work. This retains evidence and an artifact projection only; it does not create Helm Log facts or alter GitHub/Map task truth.

## Durable shape

`ArtifactJournal` stores exact caller bytes under `raw/sha256/<64-lowercase-hex>` and returns the frozen `RawArtifactRef` shape:

```ts
{ ref: 'raw:sha256:<hash>', hash: 'sha256:<hash>', mediaType }
```

The hash-derived path is generated by the journal; callers cannot turn `ref` into a filesystem path. Source identities are global: a distinct metadata sidecar is named from a hash of `sourceIdentity`, matching the SQLite uniqueness key. Its `recordId` binds the schema version, source, global identity, canonical raw reference and media type, classification, and optional `derivedFrom` reference. It is published after the raw bytes and before the projection. This preserves source/media/derivation data for a later rebuild rather than inventing it from a filename or a Pi event.

The raw file is staged with mode `0600`, flushed, hard-linked into its final hash path without replacement, and the containing directory is synced. Sidecars use the same private atomic publication. The journal root and owned child directories are mode `0700`. It rejects symlinks at every journal path it opens. These are local trusted-host file controls, not a complete worker sandbox or a claim that arbitrary host processes cannot read the directory.

## Projection boundary

`ArtifactIndexPort` is a narrow projection seam: look up by source identity, record metadata, reset, and optional close. The default `SQLiteArtifactIndex` uses Node 22's built-in `node:sqlite`, a uniquely named `helm_artifact_index` table, WAL mode, and `synchronous = FULL`. A caller may supply an index path, including a core database, without the journal changing existing directory permissions or core tables.

SQLite is explicitly non-authoritative here. `rebuildIndex()` scans only durable artifact sidecars and repopulates the supplied index. It emits no command, event, attempt, authority, or other orchestration record. The kernel owns its append-only Log records and retains raw references supplied by callers.

## Crash and integrity behavior

The journal does not report complete evidence just because a sidecar or index lookup exists.

- A simulated crash after raw publication and before metadata produces `orphan_raw` with `sourceIdentity: 'unknown'`; the journal does not fabricate source metadata.
- A simulated crash after metadata publication and before index insertion produces `unindexed_metadata`. Retrying the identical append rechecks the raw bytes and repairs the index; `rebuildIndex()` is also available.
- A missing raw file and a raw file whose bytes no longer hash to the recorded reference become `missing_raw` and `corrupt_raw`. Reads and identical retries fail rather than returning a completed artifact. `rebuildIndex()` first validates every referenced raw blob, before resetting SQLite; a failed validation leaves the prior projection intact.
- Concurrent writes with the same source identity use the identity-addressed sidecar as an atomic first-writer fence. Different bytes cause the losing sidecar publication to refuse; its already-published raw bytes remain an inspectable `orphan_raw`, and only the winning source record can be read/indexed. Equal-byte races are idempotent. A malformed pre-existing identity collision is an `ArtifactConflictError` during reconciliation/rebuild; the implementation never chooses one record or resets a partial projection.
- Duplicate exact source records are idempotent only when source, identity, bytes, media type, classification, and derivation all match.

Sensitive writes require both host policy and a trusted access context. Reads require a trusted sensitive-read context if their own metadata is sensitive or if the same raw hash has any sensitive alias, so an ordinary alias cannot bypass the sensitive policy. Redacted material is stored as a new artifact with `derivedFrom`; raw source bytes are never rewritten.

## Executed evidence

With Node `v22.22.2`:

```text

```

The standalone journal head `9aaa614` reports 19 test groups: nine contracts and ten journal groups. It covers byte preservation for event/envelope/context/gate inputs; duplicate and conflict behavior across global source identities; both crash windows; missing/tampered bytes; projection rebuild preservation; traversal rejection; file modes; sensitive policy and alias protection; and malformed-sidecar failure.

[PR #42](https://github.com/Nicegarrry/helm3/pull/42) adds the provider-free same-SQLite integration oracle. The merged combined suite reports 28 groups: nine contracts, eight kernel, ten journal, and one integration group. It proves library-level coordination between the kernel Log and artifact projection in a shared SQLite file; native producer wiring remains later work. Node prints its current experimental warning for `node:sqlite`; that warning is retained as an implementation limitation, not hidden as a production-readiness claim.

## Streaming metadata authority (2026-09-15)

Each raw hash now has a durable `authority/sha256/<hash>.json` descriptor. It records the effective classification for that content hash: a sensitive alias atomically elevates the descriptor and it never downgrades. Append and read use only their known source sidecar plus that known hash descriptor; they no longer scan the entire metadata directory for every raw Pi event. A missing or malformed descriptor refuses the read, so its absence can never be treated as evidence that an alias is ordinary. SQLite remains a rebuildable projection and is not used for this access decision.

`open()` and `reconcile()` retain the complete sidecar scan, including malformed sidecar and duplicate-identity checks. They backfill or elevate descriptors from validated sidecars, which migrates existing journals. The migration boundary is quiescent: all legacy writers must be stopped before a current-format process opens the journal. An old writer cannot be made to update a descriptor it does not know about, so mixed-version concurrent writers are unsupported and fail closed only after the next open/reconciliation scan. The 2026-09-15 deployment had no live old Pi journal writers.

The regression test writes 1,100 artifacts and uses the journal's metadata-scan observer to prove that append/read do not rescan durable metadata; it then proves that `reconcile()` still performs its full durable validation scan. It also covers deleted/corrupt descriptors, open-time backfill, stale SQLite repair, and two simultaneously open current-format journals where a sensitive alias elevates an earlier ordinary alias. On Node v22.22.2, the same direct 1,000-event append workload took 78,379 ms at `c5b4e24` and 29,359 ms after this change: a 62.5% reduction. The old hot path performed two full metadata scans per append.
